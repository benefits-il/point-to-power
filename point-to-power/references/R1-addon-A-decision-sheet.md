## נספח A - Point's Decision Sheet

טבלת החלטה תפעולית. עמודה ימנית = מה המשתמש אמר; עמודה אמצעית = מה Point ממליץ במשפט אחד קונקרטי; עמודה שמאלית = הפרק והעיקרון המבססים.

| מצב המשתמש (איך הוא ניסח את הצורך) | המלצת Point (פעולה קונקרטית במשפט) | פרק/עקרון מבסס |
|---|---|---|
| "יש לי 20 דקות מול לקוח, מה מבנה?" | בנה Atkinson 3-Act עם CTA בסוף Act I, ולא בסוף המצגת, כדי שגם אם הלקוח יוצא ב-15 הדקה ה-CTA נשמע. | פרק 7 (Atkinson), פרק 8 (Sales deck / Pitch) |
| "המנכ"ל ביקש שקף עם המספרים" | Pyramid Principle - מסקנה במשפט אחד בשקופית הראשונה, ראיות מתחת; מנכ"ל לא מחכה לדרמה. | פרק 7 (Pyramid), פרק 8 (Executive) |
| "הקהל לא טכני, יש לי גרף מורכב" | רדוקציה לפי Lie Factor 0.95-1.05 + הסבר מילולי בקריינות; אם הגרף נשאר מורכב - פצל לשני שקפים והשתמש בסיפור. | פרק 3 (Lie Factor, Knaflic), פרק 8 (Broad audience) |
| "כתבתי שקף עם 6 בולטים" | החלף ב-sentence headline + ויזואל אחד; אם זו באמת רשימה לא מסודרת עם פעלים מקבילים, צמצם ל-≤5 בולטים בכללי Doumont. | פרק 4 (Atkinson vs Doumont) |
| "מה גודל פונט?" | 24-28pt לגוף עם היררכיה כפולה (תת-כותרת ×1.5, כותרת ×2); פיץ' עסקי → Kawasaki 30pt; lecture מדעי → Doumont 18-24pt. | פרק 1.3 (סתירת Kawasaki-Doumont), פרק 8 |
| "כמה זמן יסתכל הקהל על כל שקף?" | תכנן ל-glance test של 3 שניות; אם המסר לא נקלט ב-3 שניות, השקופית נכשלה לפני שפתחת את הפה. | פרק 2.2 (Duarte glance test) |
| "מה לעשות עם speaker notes?" | לפי ז'אנר: keynote / TED → Reynolds (key phrases ≤10 מילים); sales / pitch / legal / board → Atkinson (~50 מילים, גם כ-leave-behind). | פרק 6 (Genre-based notes selection) |
| "יש לי שקף עמוס" | פצל לפי one message per slide; אל תפחד מ-N שקופיות נוספות - שקפים נוספים זולים מעומס חזותי על working memory. | פרק 2.1 (Doumont one-message), פרק 0 (CLT) |
| "תמונה דקורטיבית או אינפורמטיבית?" | Coherence Principle - כל אלמנט שאינו מלמד את המסר הוא extraneous load; הסר את הדקורטיבית או החלף בתמונה ייחודית שמקודדת את המסר. | פרק 5 (Coherence, distinctiveness), פרק 0 |
| "איך פותחים מצגת?" | Sparkline (what-is מול what-could-be) לקהל רחב; Pyramid (תשובה ראשונה) למנהלים; SCQA כפתיח כללי שמשמש כגשר לפירמידה. | פרק 7 (Sparkline, Pyramid, SCQA), פרק 8 |
| "האם חוקיים בולטים?" | כן - בתנאי ארבעת Doumont: רשימה לא מסודרת אמיתית, ≤5 פריטים, parallelism גרמטי, ללא פיסוק; אחרת לא. | פרק 4.3 (Doumont conditional) |
| "אני בונה pre-read של 12 עמודים, באיזה פורמט?" | זה Slidedoc (לא presentation); 100-250 מילים לעמוד, היררכיה טיפוגרפית עשירה, serif מותר; קובץ נפרד מקובץ ההקרנה. | פרק 0.3 (3 קטגוריות התוצר), פרק 2.5 |
| "המצגת תוקרן ותופץ אחר כך - איזה קובץ?" | שני קבצים נפרדים: presentation דלילה להקרנה + slidedoc צפוף ל-leave-behind; ניסיון לקובץ אחד שמשרת את שניהם נכשל בשני התפקידים. | פרק 0.3, פרק 2.5, פרק 8 (Sales deck) |
| "הקהל מעורב - חלק טכניים חלק לא, איך לנסח?" | התחל ב-pre-training (Mayer #9) - יישור מונחים בסיסיים ב-1-2 שקופיות; תמונה מטפורית בהקדמה + אינפורמטיבית בנתוני ליבה. | פרק 0 (Pre-training), פרק 5.5, פרק 8 (Mixed audience) |
| "כמה צבעים מותר על שקופית?" | ניגוד WCAG 4.5:1 מינימום, 7:1 לחדרים גדולים; טקסט כהה על רקע בהיר או הפוך; הימנע מאפור-על-אפור ומ-chromatic vibration. | פרק 1.5 (Contrast ratios) |
| "כמה פונטים מותר במצגת?" | שתי משפחות מקסימום (CRAP של Williams) - אחת לכותרת, אחת לגוף; וריאציות משקל (Bold/Italic) הן הדגשה, לא משפחה נוספת. | פרק 1.2 (Williams two-font ceiling) |
| "אני בונה שקופית עם נתון בודד דרמטי" | Big number יחיד גדול במרכז; לא bar chart שלם, לא טבלה - "use the numbers directly" של Knaflic. | פרק 3.5 (Knaflic chart choice) |
| "איזה גרף לנתוני זמן רציפים?" | Line graph - הקו עצמו אומר רציפות; השווה bar רק אם הנתונים קטגוריאליים, ועם zero baseline חובה. | פרק 3.5 (Knaflic - line vs bar), פרק 3.3 (Lie Factor) |
| "פאי או בר?" | כמעט תמיד bar - המוח קורא אורכים יותר מדויק מזוויות; פאי רק עד 8 פלחים, הגדול מתחיל בשעה 12, סדר לפי גודל. | פרק 3.5 (Knaflic, Duarte pie rules) |
| "האם להוסיף אנימציות מעבר?" | הסר; הן extraneous load שמפר את Coherence Principle (d=0.86 נגד); רק אם האנימציה מקודדת נתון (תהליך לאורך זמן), השאר תחת Temporal Contiguity. | פרק 0 (Coherence + Temporal), פרק 5.4 |
| "צריך לסיים TED talk של 12 דקות, מה המבנה?" | Gallo 9 secrets + Atkinson דחוס; פתיחה תוך 30 שניות, רעיון אחד מזוקק, תמונה מטפורית full-bleed כברירת מחדל. | פרק 7 (Gallo), פרק 8 (TED ≤18min) |
| "הדובר חושש שישכח את הסקריפט באמצע פיץ' לחוץ" | Atkinson Notes Pane מלא ~50 מילים פר שקופית - רשת ביטחון תחת לחץ; וגם משמש handout אם המאזין רוצה לחזור. | פרק 6.3 (Atkinson notes) |
| "האם לקרוא בקול את הבולטים על המסך?" | לעולם לא - הפרה ישירה של Redundancy Principle (d=0.86 נגד); הקהל קורא מהר ממך, אתה הופך לחסר רלוונטיות במצגת שלך. | פרק 4.1, פרק 6.1, פרק 0 (Redundancy) |
| "כותרת-נושא או כותרת-משפט?" | כותרת-משפט (sentence headline) - משפט שלם פעיל שמבטא טענה; קריאה רק של הכותרות ברצף חייבת להחזיר את הסיפור. | פרק 2.4 (Atkinson assertion headlines) |
| "יש לי תמונת clip art - להשתמש?" | לא; distinctiveness נמוך = שליפה רועשת; החלף בתמונה ייחודית-לקהל-הזה (Duarte: ריאליזם > מטאפורה גנרית). | פרק 5.3 (distinctiveness), פרק 5.5 (Duarte) |
| "המצגת בעברית - איזה פונט?" | sans-serif עברי (Rubik / Heebo / Assistant) כברירת מחדל להקרנה; David / serif עברי שמורים ל-slidedoc מודפס. | פרק 1.1 (sans-serif default) |
